# funk reports one verdict per file, as text for people or as JSON lines for tools

Status: accepted

## Context

The roadmap requires structured diagnostics: IR locations, text for people,
JSON for agents. ADR-2026-10-30-0815 splits rejections in two: a text that
does not decode is a parse error with a text position, and a module that
breaks a rule is a validation error. The harness (#13) compares the verdict
of `funk verify` with that of `fir-ref validate` (#10), never the wording.

## Decision

- **Commands.** `funk fmt [--check | --write] [--json] FILE...` parses each
  file and prints its canonical form. It does not validate: every module
  that parses has a canonical form, since the printer is the formatter
  (P3). `--check` lists the files that are not canonical, and `--write`
  rewrites them. `funk verify [--json] FILE...` parses and validates each
  file. `-` is standard input.
- **Exit status.** 0 when every file is accepted, and canonical under
  `--check`; 1 when one is rejected, or not canonical under `--check`; 2 on
  a usage or I/O error.
- **Text.** Diagnostics go to standard error, one per line:
  `FILE:LINE:COL: parse error: REASON`, or
  `FILE: validation error in @f ^block op N: MESSAGE (at @R = LOCATION)`,
  with the parts that apply.
- **JSON.** With `--json`, each file gets one JSON object on one line of
  standard output: `file`, `verdict` and `diagnostics`. The verdict is
  `accepted`, `parse-error`, `validation-error` or `io-error`. A
  diagnostic has a `kind` (`parse-error`, `validation-error` or
  `io-error`) and a `message`. A parse error adds `line` and `column`
  (UTF-8 bytes from 1). A validation error adds `func`, `block`, `op` (the
  index in its block) and `loc`, each `null` when it does not apply; `loc`
  is `{"ref": N, "location": "..."}`, with the location as the table prints
  it, or `null` when the table lacks the reference. `fmt` adds `canonical`,
  and without `--check` or `--write` the canonical `text`.
- **How many.** The parser stops at its first error; the verifier reports
  every rule the module breaks.
- **Messages are for people.** Tools compare verdicts, kinds and positions,
  never message text.

## Consequences

- #13 runs `funk verify --json` and compares `verdict` with
  `fir-ref validate`'s.
- Agents get every validation error of a module in one run.
- A new field is added without breaking readers; renaming one, or a
  verdict, takes a new ADR.
