# `fir-ref` treats `freeze` as a choice, and native results pass by set membership

Status: accepted; extended by ADR-2026-10-30-2135

## Context

The human made this direction call on 2026-10-29, after the M0 epic
([#5](https://github.com/pmatos/funk/issues/5)) was written, together with
two additions: the Lean soundness proofs and declared results with witnesses.
[#7](https://github.com/pmatos/funk/issues/7) records it.

`freeze` of poison yields an arbitrary but fixed value (S1,
ADR-2026-10-29-2006). So a function's behaviour is a set of outcomes, not one
outcome. The reference interpreter (S7, ADR-2026-10-29-2009) must compute that
set, and the differential harness must check native results against it by
refinement (S4, ADR-2026-10-29-2008).

## Decision

- **Choice effect.** The interpreter's monad has a `choose w` effect. `freeze`
  of poison calls it, and every use of the result sees the same bits. With the
  set instance of the monad, the interpreter defines the semantics: the set of
  behaviours over all choices.
- **Two `fir-ref` modes** run the same interpreter. Exhaustive mode tries every
  choice sequence, up to a budget on the total number of choice bits, and
  prints the set of outcomes. Scripted mode takes a choice sequence and prints
  one outcome.
- **Soundness proofs.** Lean proves that exhaustive mode, within its budget,
  returns exactly the semantic set, and that scripted mode returns a member of
  it.
- **Harness rule.** A native result passes if it is in the set. A test whose
  choices exceed the budget is invalid, unless it declares its allowed
  results. A test is also invalid if any outcome in its set is UB, because
  source UB allows any result.
- **Declared results.** A test may list its allowed results. Each listed value
  carries a witness choice sequence, and scripted mode must reproduce the
  value from it. Seeded random runs check that no sampled outcome falls outside
  the list, and that none is UB.

## Alternatives

- **Pick one fixed value** for `freeze` of poison. Correct native code fails.
- **Accept any native value when `freeze` is involved.** Misses bugs where uses
  of one frozen value disagree, such as `x xor x` returning non-zero.
- **Log native choices and replay them.** Changes the code under test, and
  breaks once passes move freezes.
- **SMT checking.** That is S8, still undecided.

Prior art: Vellvm's propositional and executable handlers, CompCert's `-all`
interpreter mode, Cerberus's exhaustive mode, WebAssembly's `either` result
patterns, and Miri's many-seeds mode.

## Consequences

- The interpreter is written against an abstract monad, so the choice effect
  needs no change to its structure.
- Exhaustive mode grows exponentially with the number of choice bits. A test
  that freezes a wide value, such as `x xor x` at `i64`, declares its results
  and a witness for each.
- The proofs tie the executable modes to the semantic set, so the oracle the
  harness runs is the semantics the spec defines.
- A poison outcome in the set still matches any native value, as S4 requires.
- For a test with declared results, the checks that no outcome falls outside
  the list and that none is UB are by sampling, so they can miss a rare
  outcome.
- This ADR does not say how the harness treats a set that contains fuel
  exhausted, which stands for non-termination but depends on the fuel budget.
  That is open, and the differential harness
  ([#13](https://github.com/pmatos/funk/issues/13)) records it.
