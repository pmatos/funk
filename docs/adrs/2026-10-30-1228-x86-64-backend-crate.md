# Each target is a crate of its own, and register allocation and passes live in generic crates

Status: accepted
Tier: direction; area: x86-64-backend

## Decision

- **One crate per target.** The x86-64 backend is the library
  `crates/funk-x86-64`. It holds only what is specific to x86-64: assembly,
  the ABI, frames, instruction choice and the entry point. A later target is a
  crate of its own.
- **Generic crates for what is not target-specific.** `funk-codegen` holds
  machine code over virtual registers, liveness, the register allocators and
  the instruction scheduler. `funk-opt` holds the optimization passes on fir.
  Neither knows any target. Register allocators sit behind one interface, so
  that others can be added and compared. Linear scan is the first.
- **Dependencies point one way.** `funk-ir` depends on no other funk crate. A
  target crate may depend on `funk-ir` and `funk-codegen`. The driver `funk`
  depends on all of them.
- **One lowering file per op family** in a target crate, as in `funk-ir`'s
  dialects. An op with no lowering is reported at its location, never skipped.
- **No third-party crates.** funk writes its own allocator. Its speed is
  compared with `regalloc2` later.

The human ruled the split into generic crates, linear scan behind a modular
interface, and writing our own allocator on 2026-11-12, in
[#164](https://github.com/pmatos/funk/issues/164#issuecomment-6820504273).

## Why

G0 (ADR-2026-10-29-2016) asks that no target be built into the IR, and M7 and
M8 bring more targets. An allocator or a pass built inside the x86 crate would
have to be moved out later, after code had come to depend on x86 details.
Keeping each target crate small also keeps it readable in one pass.

## Rejected alternatives

- **Everything in the x86 crate until a second target arrives.** This was the
  M0 rule. A real allocator and the optimizer start in M2, well before a
  second native target, and moving them later costs more than starting
  generic.
- **The backend inside `funk-ir`.** It would tie the IR library to one target.
- **Using `regalloc2`.** It would be funk's first third-party crate in the
  backend, and the human chose to write our own.
