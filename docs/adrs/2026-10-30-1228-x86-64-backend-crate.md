# The x86-64 backend is the crate funk-x86-64, with one lowering file per op family

Status: accepted

## Context

[#12](https://github.com/pmatos/funk/issues/12) adds the first backend: a
naive x86-64 backend behind `funk build`. ADR-2026-10-30-1030 puts every
crate under `crates/` and allows no third-party crates yet.
ADR-2026-10-30-1146 gives each op family of the core dialect a file of its
own in `funk-ir`, so that a later family adds a file and a line. The
families of #14 to #22 each add their ops to the backend too. M6 needs an
arm64 backend later, and G0 (ADR-2026-10-29-2016) asks that no target be
built into the IR.

## Decision

- **One crate per target.** The x86-64 backend is the library
  `crates/funk-x86-64` (`funk_x86_64`). It depends only on `funk-ir`, and
  `funk-ir` does not depend on it. The driver `funk` depends on both. A
  later target is a crate of its own. Code that two targets share moves to
  a shared crate when the second target arrives, not before.
- **Modules by responsibility.** `asm` writes assembly text, `width` says
  how a value of `iN` lives in a register (ADR-2026-10-30-1231), `abi` says
  how a function looks from outside (ADR-2026-10-30-1232), `frame` lays out
  a function's slots (ADR-2026-10-30-1230), `lower` lowers ops, `entry`
  writes an executable's entry point (ADR-2026-10-30-1233), and `tools` runs
  the assembler and the linker (ADR-2026-10-30-1229).
- **One file per op family.** `lower/` mirrors `funk-ir`'s
  `dialects/core/`: `constant.rs`, `arith.rs` and `control.rs` now. Each
  file maps op names to lowering functions. `lower/mod.rs` asks each family
  in turn, so a new family adds a file and one line there. An op with no
  lowering is reported at its location, never skipped.
- **Diagnostics are `funk_ir::Diagnostic`s**, located as the verifier
  locates them, so the driver reports both alike.
- **Still no third-party crates.** The backend writes text and runs
  external tools, which needs only the standard library.

## Alternatives

- **The backend inside `funk-ir`.** It would tie the IR library to one
  target and grow it past what an agent reads in one pass.
- **A generic `funk-codegen` crate with an `x86_64` module.** There is no
  second target to share code with yet, so the split would be a guess.

## Consequences

- `funk-ir` stays target-free, and its users need not build a backend.
- Each family ticket touches one new file in `lower/` and one line in
  `lower/mod.rs`.
